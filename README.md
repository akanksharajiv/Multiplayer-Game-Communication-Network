# CN Project: Multiplayer SDN Game (D1 + D2)

This archive contains the team's D1 three-player UDP multiplayer demonstration and D2 performance, QoS, dynamic congestion and robustness experiments.

## Important project files

- `multiplayer_peer.py`: three-player UDP peer used by the unified D1 demonstration and the Player 2 outage/recovery test.
- `game_sdn_controller.py`: D1 controller. Its learned forwarding rules use protocol-aware matches so broad MAC rules do not pre-empt the game-traffic QoS rule.
- `game_sdn_controller_person3_D2.py`: Person 3-approved D2 controller. The dynamic test verifies its SHA-256 before launch. Do not edit this file casually; the integrity check is intentional.
- `launch_project.py`: shared Mininet, OVS, Ryu and QoS setup helpers, plus the original D1 launcher.
- `multiplayer_demo.py`: D1 multiplayer demonstration; `--robustness` enables the simulated Player 2 outage/recovery test.
- `d2_performance_test.py`: D2 baseline and static QoS benchmarks.
- `d2_dynamic_person2_test.py`: D2 dynamic QoS benchmark using the approved controller directly.
- `run_all.py`: sequential master workflow for the D1 demonstration and D2 tests.
- `receiver_new.py`: receiver used by `launch_project.py`. The shared receiver path is configured to this actual filename.

## Environment requirements

Run the project in an Ubuntu VM with sudo/root privileges. This project uses Mininet and Open vSwitch and cannot be fully executed from macOS or a normal Python-only environment.

System packages/commands required:

- Mininet and its Python package
- Open vSwitch (`ovs-vsctl`, `ovs-ofctl`)
- `timeout`
- `iperf3` for D2 baseline, static and dynamic performance tests
- Python 3 for the Mininet-side scripts
- A separate Ryu virtual environment at `.venv-ryu/bin/ryu-manager`

Typical Ubuntu package installation (package names may vary by Ubuntu release):

```bash
sudo apt update
sudo apt install mininet openvswitch-switch iperf3 python3-venv python3-pip
```

Create the Ryu environment using a Python version compatible with the Ryu release used by the team. The launchers expect the executable at `.venv-ryu/bin/ryu-manager`:

```bash
python3 -m venv .venv-ryu
source .venv-ryu/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-ryu.txt
deactivate
```

The Ryu environment is deliberately not bundled in the ZIP. Virtual environments contain machine-specific paths and must be recreated on the target Ubuntu VM.

## Quick prerequisite check

From this project directory:

```bash
python3 -m compileall -q .
command -v ovs-vsctl
command -v ovs-ofctl
command -v iperf3
 test -x .venv-ryu/bin/ryu-manager
```

The Python launchers perform their own runtime checks too. D2 performance tests explicitly stop before network creation if `iperf3` is missing. Do not start a second Mininet topology or Ryu controller while a previous run is still active.

## Run the complete workflow

```bash
sudo python3 run_all.py
```

The master workflow runs these stages sequentially, stopping at the first failed stage and preserving all evidence already produced:

1. D1 three-player multiplayer demonstration
2. D2 Player 2 simulated disconnection/reconnection robustness test
3. D2 baseline performance test
4. D2 static QoS performance test
5. D2 dynamic QoS activation and recovery test

Useful shorter runs:

```bash
sudo python3 run_all.py --skip-robustness
sudo python3 run_all.py --skip-d2
```

Individual commands are also supported:

```bash
sudo python3 multiplayer_demo.py
sudo python3 multiplayer_demo.py --robustness
sudo python3 d2_performance_test.py --mode baseline
sudo python3 d2_performance_test.py --mode static
sudo python3 d2_dynamic_person2_test.py
```

The original D1 launcher remains available separately:

```bash
sudo python3 launch_project.py
```

It opens the Mininet CLI after starting the original sender/receiver demonstration. Type `exit` at `mininet>` to stop it cleanly.

## Dynamic QoS reproducibility

The dynamic test explicitly injects the configuration below into the Ryu process. It does not depend on environment variables left in the user's shell:

| Setting | Value |
|---|---:|
| Congestion threshold | 50% |
| Recovery threshold | 30% |
| Consecutive congestion samples | 2 |
| Consecutive recovery samples | 3 |
| Monitor interval | 2 seconds |
| Policy cooldown | 6 seconds |

These thresholds match the successful archived dynamic runs. Every new dynamic run records the full controller environment, controller SHA-256 and selected thresholds in its run folder. The approved D2 controller source itself is not modified by this repair.

## Robustness test pass criteria

The robustness test now returns a non-zero exit status unless all of the following are observed:

- Player 2 logs both `DISCONNECTED (simulated)` and `RECONNECTED`.
- Players 1 and 3 each receive acknowledgements from Player 2 before the outage.
- Players 1 and 3 each record at least one timeout to Player 2 during the outage.
- Players 1 and 3 each receive acknowledgements from Player 2 after recovery.
- Players 1 and 3 continue acknowledging one another during and after Player 2's outage.

The multiplayer CSV now includes `elapsed_s`, which lets the test classify records against the configured outage window instead of merely checking that log messages exist.

## Interpreting results honestly

A successful Python compile or controller unit test does not certify live OpenFlow, HTB queueing or Mininet behaviour. The final acceptance check is to run the workflow in the team's Ubuntu VM and inspect each run's `summary.txt`, `summary.json`, controller log, flow dump and CSV files. Do not describe a stage as passed unless its process exits successfully and its generated verification conditions are satisfied.

Unanswered UDP update records are not automatically equivalent to one-way packet loss. They can include late/missing acknowledgements, endpoint downtime or other causes; use the exact metric label in the report.

## Troubleshooting

- **Missing `receiver_new.py`:** restore the file from this archive. `launch_project.py` now points to `receiver_new.py` consistently.
- **Missing `iperf3`:** install it with `sudo apt install iperf3`; D2 tests check for it before starting Mininet.
- **Missing Ryu:** recreate `.venv-ryu` and install `requirements-ryu.txt`.
- **Mininet import error:** run with the Ubuntu system Python that has the Mininet package installed, not a separate custom Python without Mininet.
- **Existing bridge/controller:** exit the old `mininet>` session and stop the old Ryu process before starting another run.
- **Dynamic test fails its approved-controller hash check:** do not remove the check to force execution. Restore the exact approved `game_sdn_controller_person3_D2.py` file and verify its SHA-256 with the team.
- **A stage fails:** inspect the run folder named in its terminal output. Earlier stages are not deleted by `run_all.py`.
